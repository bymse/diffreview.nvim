# Spec 004: Expose The Review Lifecycle

## Goal

Expose explicit setup plus `ReviewStart` and `ReviewStop` through the public module, with `review.lua` owning asynchronous start, cancellation, notifications, rollback, and the single active review lifecycle.

## Prerequisites

Spec 001, Spec 002, and Spec 003 must be complete.

## Context

Read `specs/CONTEXT.md` for the public behavior, comparison ownership, configuration decisions, lifecycle states, cancellation constraints, and deferred features.

## Tasks

1. Replace the hello placeholder in `lua/diffreview/init.lua` with public `setup`, `start`, and `stop` functions. Remove import-time notification and the `hello` interface; no compatibility shim is required.
2. Update `lua/diffreview/config.lua` to distinguish setup input from normalized configuration. Setup input has optional top-level `layout: 'horizontal'|'vertical'` and `view: 'side_by_side'|'inline'`; normalized `Config` has both fields required and defaults them to `horizontal` and `side_by_side`. `setup()` and `setup({})` are valid; non-table inputs, unknown fields, mistyped fields, and unsupported values raise a synchronous public-interface error before commands or configuration are committed.
3. Make `setup(options)` explicit and single-use. The first valid call stores normalized configuration and registers `ReviewStart` and `ReviewStop`; every later call fails, including calls with identical options. A failed initial validation must not consume setup or leave partially registered commands.
4. Register `ReviewStart` with positional command arguments and manually enforce a maximum of two revisions; register `ReviewStop` with no arguments. Command invocation uses Neovim’s current working directory. Keep `plugin/diffreview.lua` as a load guard that requires the public module without registering commands before setup.
5. Define public `ReviewStartOptions` with optional `cwd: string`, `from: string`, and `to: string`. Both `diffreview.start()` and `diffreview.start({})` are valid after setup and use Neovim’s current working directory with zero revisions. Reject non-table inputs, unknown fields, non-string or empty-string values, and `to` without `from` through the review notification contract without starting a coroutine. The command adapter maps its zero-to-two positional revisions into this options shape and does not expose a command-line path option.
6. Add `lua/diffreview/review.lua` as the owner of module-level `idle`, `starting`, and `active` lifecycle state. Its `start(config: Config, options: ReviewStartOptions): nil` interface validates synchronously, creates and resumes the orchestration coroutine, and returns immediately; its `stop(): nil` interface operates on the current lifecycle and also returns immediately. A coroutine body error must be caught, partial UI cleaned, lifecycle returned to idle, and one error notification emitted. Keep lifecycle state private and verify it through public behavior rather than exposing a general state-management interface.
7. On start from idle, mark the lifecycle starting before the first asynchronous yield, create cancellation state, invoke `diffreview.diffs.load_review`, and reject any competing start until the operation settles. On a non-empty successful load, create one `ReviewUi`, project `LoadedDiffs.files`, and commit an active session retaining normalized configuration, `LoadedDiffs`, and `ReviewUi`. Do not create an active session or full diff snapshots for an empty result.
8. Own all start/stop lifecycle notifications in `review.lua`. Invalid start options, conflicts, Git/diffs failures, UI failures, and unexpected coroutine failures use `vim.log.levels.ERROR`; empty comparisons and idle stops use `vim.log.levels.INFO`; successful active stops and canceled starts use `vim.log.levels.INFO`. Cancellation emits only the stop notification, and the canceled start must remain silent afterward. Tests assert notification category, level, and count without pinning incidental diagnostic wording.
9. Roll back to idle after every startup failure. If UI creation or projection partially succeeds, invoke `ReviewUi:cleanup()` before discarding it. Never replace or mutate an already active review when rejecting a conflicting start.
10. Extend `lua/diffreview/async.lua` with an opaque `AsyncOperation` created by `new_operation(): AsyncOperation`, canceled by `cancel(operation): nil`, and queried by `is_canceled(operation): boolean`. Allow `async.system(cmd, options, operation?)` to associate its current `vim.SystemObj` with the operation while preserving existing behavior when no operation is supplied. Extend the Spec 001 loader interface to `diffreview.diffs.load_review(options: DiffLoadOptions, operation: AsyncOperation|nil)` so cancellation remains separate from the validated options table. Extend `diffreview.diffs.git.get_repo(dir, operation?)` to retain that optional operation and pass it to every repository command without changing existing `GitRepo` method signatures or uncancelled callers.
11. Cancel marks the operation before killing its current process. The process callback remains responsible for scheduling one final coroutine resume, but guards must prevent double resume. Extend `GitResult` with optional `canceled: boolean`; an operation canceled before or during a repository command returns `ok: false`, `canceled: true`, and no Git error. Extend the Spec 001 `DiffLoadError.kind` union with `'canceled'`; `load_review` maps a canceled Git result or canceled operation to that kind with no low-level diagnostic detail. `review.lua` suppresses this canceled load result after `ReviewStop` has invalidated the operation. Review also checks the operation identity or generation after every asynchronous completion and before UI creation or active-state commit, so a scheduled late callback cannot notify an obsolete error, leak UI, or reactivate a stopped review.
12. Implement stop transitions: from starting, cancel and invalidate the operation, clean any partial UI, notify once, and return to idle; from active, call `ReviewUi:cleanup()`, release the session, notify, and return to idle; from idle, leave state unchanged and notify that no review is active.
13. Add `tests/integration/review_tests.lua` and register it in `tests/integration/init.lua`. Test `review.lua` directly with normalized configuration for cwd fallback and explicit cwd, successful non-empty quickfix display, empty comparison, load and UI failures, conflicting starts, active cleanup, idle stop, cancellation during Git loading, late completion suppression, notification levels/counts, and preservation of unrelated editor resources. Restore patched notifications and async/process callables after every case, stop active reviews during teardown, and reload the private review module only when necessary to isolate singleton state; do not add a production reset interface.
14. Replace the hello assertions in `tests/integration/plugin_test.lua` and `tests/functional/plugin_test.lua`. Keep setup-dependent public-interface assertions in one ordered test flow per test process: verify silent plugin loading and absent commands, call valid setup once, verify both commands and public Lua options, exercise command argument rejection and cwd behavior against a real repository, stop the review, then verify repeated setup fails without replacing commands. Other integration lifecycle cases must call `review.lua` directly as described above so they do not require repeated public setup. Retain only plugin-load assertions that remain meaningful.
15. Do not add quickfix entry activation, full `DiffViewModel` loading, reviewed-state changes, comments, persistence, refresh, automatic setup, command-line repository path options, or implicit review replacement.

## Verification

2. Run `just format`, then `just format-check`.
3. Run focused lifecycle cases with `just test-integration <exact_test_name>` and focused command cases with `just test-functional <exact_test_name>` while developing.
4. Run `just test-integration` and `just test-functional` to prove orchestration and public command behavior.
5. Run `just test` as the final regression gate across all categories.
